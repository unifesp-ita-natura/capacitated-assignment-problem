# External demand features (calendar + macro)

Generated by `uv run python -m src.processamento_dados.external_features` (see
`src/processamento_dados/external_features.py`) from `demanda_level_by_state.csv`
and `demanda_shape_by_state.csv` (see `docs/context/demanda-level-shape.md` for
those files). Written to `data/processed/` (gitignored — regenerate locally).

Scope decided with the user: IPCA (inflation) is **deliberately excluded** — it's
a national series, identical for all 633 sectors within a cycle, collinear with
any time trend, and the target is item counts, not revenue (see
`docs/plans/forecasting-feature-roadmap.md` Etapa 8, which rejects it for the same
reason).

## Sources

All data comes from one of two mechanisms — nothing is scraped from HTML:

1. **Calendar features** (`src/processamento_dados/external_calendar.py`) — pure,
   offline, computed from the `holidays` Python package (national + all 27 UF
   state holidays) plus hand-coded date rules. No network calls.
2. **Macro indicators** (`src/processamento_dados/external_macro.py`) — fetched
   from IBGE's official SIDRA JSON API (PNAD Contínua), cached to
   `data/external/raw/*.json` (gitignored) so repeated runs don't re-hit the
   network.

## `demanda_level_by_state_with_external.csv` — adds to `demanda_level_by_state.csv`

One row per (sector, estado, ciclo), same key as the source file. Added columns:

| column | meaning |
|---|---|
| `n_national_holidays` | count of Brazilian national holidays inside the cycle's day window |
| `n_state_holidays` | count of the sector's UF-specific holidays (excludes dates already counted as national) inside the window |
| `n_dia_das_maes` / `n_dia_dos_namorados` / `n_dia_dos_pais` / `n_natal` | count of that commemorative date inside the window (0 or 1) |
| `n_bolsa_familia_window_days` | count of days inside the window that fall in the Bolsa Família disbursement proxy (see caveat below) |
| `has_quinto_dia_util` | whether the month's 5th business day (common payday) falls inside the window |
| `periodo` | SIDRA quarterly period code derived from the cycle's opening date (e.g. `202602` = Q2 2026) |
| `taxa_desocupacao` | PNAD Contínua UF-level unemployment rate for `periodo`, or `NaN` if not yet published |
| `rendimento_medio` | PNAD Contínua UF-level average income for `periodo`, or `NaN` if not yet published |

## `demanda_shape_by_state_with_external.csv` — adds to `demanda_shape_by_state.csv`

One row per (sector, estado, ciclo, day), same key as the source file, **minus**
the rows dropped by the out-of-cycle-window filter (see caveat below; default
behavior). Added columns:

| column | meaning |
|---|---|
| `data_pedido` | the row's real calendar date, reconstructed from `relative_date × cycle_duration` and the cycle's opening date (the source file only carries the [0, 1] fraction, not a calendar date) |
| `is_national_holiday` / `is_state_holiday` | per-day holiday flags |
| `is_dia_das_maes` / `is_dia_dos_namorados` / `is_dia_dos_pais` / `is_natal` | per-day commemorative-date flags |
| `is_quinto_dia_util` | whether this day is the month's 5th business day |
| `is_bolsa_familia_window` | whether this day falls in the Bolsa Família disbursement proxy |
| `periodo`, `taxa_desocupacao`, `rendimento_medio` | same as the level file, keyed off `data_pedido`'s quarter instead of the cycle's opening date |

## Caveats

- **Bolsa Família is a simplified proxy, not the real payday.** The real policy
  staggers payments across the last ~10 business days of each month by the final
  digit of each beneficiary's NIS number; no bulk machine-readable official source
  publishes that per-digit mapping (only a monthly PDF on gov.br). This module
  flags "last 10 business days of the month" as one national window instead —
  treat `is_bolsa_familia_window`/`n_bolsa_familia_window_days` as a coarse signal.
- **Macro indicators lag by about a quarter.** PNAD Contínua's most recent
  published quarter as of 2026-10 is Q2 2026 (`202602`); Q3 2026 (`202603`, which
  covers the tail of the demand window through 2026-07-22) isn't published yet.
  Rows in that quarter get `NaN` for `taxa_desocupacao`/`rendimento_medio` rather
  than a stale or fabricated value — don't impute these without deciding that's
  the right call for the model being built.
- **~4.75% of `demanda_shape_by_state.csv` rows have `relative_date` outside
  [0, 1]** (observed range -3.29 to 6.14), meaning their reconstructed
  `data_pedido` would fall outside that row's own cycle window. This reflects the
  by-state pipeline's `cycle_duration`/`date` being computed per (sector, estado)
  subgroup while the underlying order dates aren't — a few orders land outside
  the subgroup's own nominal window. **By default these rows are dropped**
  (`run(drop_out_of_cycle_window=True)`, the default; CLI flag
  `--keep-out-of-cycle-window` to keep them instead) — the shape output has
  79,917 rows, not the source file's 83,906. The level file is unaffected (it's
  per-cycle, not per-day).
- Doesn't reconcile row-for-row with anything beyond `demanda_level_by_state.csv`/
  `demanda_shape_by_state.csv` themselves — see that file's own caveats in
  `docs/context/demanda-level-shape.md` about not mixing it with
  `demanda_level.csv`/`demanda_shape.csv`.

## SIDRA tables used

- Unemployment: table `6468`, variable `4099` ("Taxa de desocupação ... 14 anos ou
  mais"), no classification needed.
- Income: table `5436`, variable `5932` ("Rendimento médio mensal real ...
  habitual, trabalho principal"), restricted to classification `2` ("Sexo"),
  category `6794` ("Total").
