# `demanda_level.csv` and `demanda_shape.csv`

Generated by `uv run python -m src.processamento_dados.pipeline` (see
`src/processamento_dados/pipeline.py`) from the Simulador workbook's "Base
Demanda" sheet, joined to its calendar sheet. Written to `data/processed/`
(gitignored — regenerate locally, don't expect them in the repo).

## Domain

- **`cd_setor`** — a sector: a commercial grouping of ~1,500 consultoras
  (sales reps). Membership is each consultant's own choice, **not**
  geographic — the same sector routinely spans several states/cities (see
  `docs/context/natura-client-answers.md`). 633 distinct sectors.
- **`ciclo`** — a sales cycle, encoded as `<ano><nn>` (e.g. `202601` = cycle
  1 of 2026). 12 cycles observed (`202601`..`202612`), i.e. one year of
  history. Each sector appears in ~10 of the 12 cycles on average (not every
  sector sells every cycle).
- Date range covered: **2025-12-05 to 2026-07-22**.
- There is **no state/city/geography column** in either file — the Simulador
  workbook's demand sheet never carried it. (A separate raw-base pipeline,
  `src/forecasting/dataset.py`, does have real per-row `estado`; see that
  module if geography is needed.)
- No capacity, CD (distribution center), block, or sub-block info in these
  two files either — this is pure historical demand, decoupled from the
  assignment the optimizer decides.

## `demanda_level.csv` — one row per (sector, cycle)

| column | meaning |
|---|---|
| `cd_setor` | sector id |
| `ciclo` | cycle id, `<ano><nn>` |
| `date` | the cycle's opening date (shared by every sector in that cycle) |
| `cycle_duration` | length of the cycle in days (ranges 7–29, mostly ~21) |
| `total_pedidos` | total orders placed by the sector in the cycle |
| `total_volumes` | total order volume |
| `total_itens` | total items ordered — the main demand metric, mean ≈45k, range 14–185,779 per (sector, cycle) |

6,276 rows = 633 sectors × ~10 cycles each.

## `demanda_shape.csv` — one row per (sector, cycle, day)

Same (sector, cycle) totals broken down by calendar day within the cycle:

| column | meaning |
|---|---|
| `cd_setor`, `ciclo` | same as above |
| `data_pedido` | the calendar date of this row |
| `relative_date` | day's position within the cycle, in [0, 1] (0 = cycle opens) |
| `total_pedidos`/`total_volumes`/`total_itens` | that day's demand |
| `ciclo_total_*` | the (sector, cycle)'s full-cycle total (same number as `demanda_level`, repeated per day) |
| `share_*` | that day's fraction of the cycle total (`total_*` / `ciclo_total_*`) |

120,074 rows. Used to model the within-cycle "shape" of demand (which days
of a cycle see more orders), separately from the "level" (how big the cycle
total is).

## How these are used

`src/forecasting/data.py` builds forecasting inputs from these two files:
`build_cycle_totals` (level → one total per sector-cycle) and
`build_shape_observations` (shape → day-offset + order-share per
sector-cycle). `src/forecasting/level.py`/`shape.py` then forecast each
piece separately and recombine them (`model.forecast_future_cycles`) into a
daily forecast per sector for a future cycle.

## Sibling files with a state column

`uv run python -m src.processamento_dados.pipeline_by_state` produces two
more files with the **same column names** as above, plus `estado`, at one
row per **(sector, state, cycle)** instead of per (sector, cycle):

- `data/processed/demanda_level_by_state.csv` — 9,617 rows, 633 sectors ×
  ~2.2 states each on average (1–8 states per sector).
- `data/processed/demanda_shape_by_state.csv` — 83,906 rows. Note: unlike
  `demanda_shape.csv`, this only carries `total_itens`/`share` (one metric,
  items) — no `total_pedidos`/`total_volumes` breakdown yet.

These are a **sibling**, not a replacement: they're built from a different
raw source (`data/raw/Unifesp_Demanda_v2.csv`, the only file with a real
per-row `estado`) joined to the same Simulador calendar for open/close
dates, not from the Simulador "Base Demanda" sheet. Their totals won't
reconcile row-for-row with `demanda_level.csv`/`demanda_shape.csv` — the two
raw exports don't agree on totals for the same (sector, cycle) even before
any state split (checked: only ~39% of rows share a key, and matched rows
differ by a median of ~1,169 items). Also, because `Unifesp_Demanda_v2.csv`'s
history runs 2024–2026 while the calendar only knows about 2026 cycles
(`202601`–`202619`), ~65% of its rows get dropped as unmatched — expect less
history here than in `demanda_level.csv`.

A sector is a commercial grouping of consultants, not a geographic one (see
`docs/context/natura-client-answers.md`) — most sectors genuinely span
several states, so splitting by state is not resolving a data error, it's
exposing real heterogeneity within a sector. See
`src/processamento_dados/pipeline_by_state.py` and
`src/forecasting/dataset.py`'s `demand_unit_id`/`resum_to_sector` for the
mechanics.
